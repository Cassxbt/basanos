In plain terms

Three steps. One honest answer.

Audit contests pay bug hunters for findings a judge accepts. Many rejections are checkable before submission: a wrong line, a known issue, a missing proof. Basanos checks for those before you hit submit.

The verdicts

Six answers, each with a next step.

Basanos asks three times. It gives automatic advice only when all three agree, no code rule had to overrule a model, and the advice is not a “no”. Everything else needs your review. Every verdict is advice, not a guarantee.

Ready

The code supports the claim, the proof is in the finding, and it is not a known issue.

Submit it.
Needs proof

Plausible, but something is still unshown. The verdict lists the suggested checks.

Add the listed proof.
Blocked by code

Something in the audited code stops the attack. The verdict names the line.

Re-check that line.
Known or out of scope

Already in the contest's known issues or bot report, needs a trusted admin to misbehave, or targets code outside scope.

Usually: don't submit.
Citation broken

No link points at audited code the finding actually talks about. Caught by code, at no cost.

Fix the links.
Held for your review

The text tried to instruct the reviewer, or a screen held it. Nothing was decided.

Read it yourself.
Is it reading the code?

Fix the bug, and the verdict moves.

These 2024 findings could be in a model's training data. So we fixed each award-winning bug on a branch and ran the same finding again. The verdict moved with the code, which shows it reads the source. It does not prove the models have never seen these contests.

Why it matters

Contest judges triage thousands of findings. Some cite a line that says something else, repeat what the bot report already caught, or claim a loss nobody showed. Each of those costs a judge time and a hunter the payout. The fix is a touchstone, not another model.
