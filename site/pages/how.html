How it decides

The cheap model reads. Code has the last word.

Most agent pipelines hand one frontier model every step. Basanos splits the work by what each step needs: deterministic checks in code, the heavy reading on an open model at a thirteenth to a hundredth of the input price, and one small guarded decision on SERV, repeated three times because a single pass does not agree with itself.

The Touchstone Pass

The Touchstone Pass, step by step.

Each step can stop the finding. Code runs first and costs nothing. The models only see what code could not settle, and code still has the last word on what they say.

04 · SERV decision · consensus

One bounded call per pass. Act only when all three agree.

SERV Reasoning reads each evidence record next to the contest's own rules and makes one bounded decision, with a request id. To call a finding known or out of scope, it must quote the rule it relies on, and code checks the quote. Code then caps the decision. A single pass agrees with itself about two times in three, so only a unanimous verdict that code did not overrule, and that is not a “no”, is given as automatic advice.

SERV Reasoning

Two jobs. A Prompt Guard front door on the raw finding before the open model, which has no guard, reads it. Then one bounded decision per pass with serv_prompt_guard on, returning a request id for every verdict.

{{loc:src/verdict.ts:export async function screen}} · {{loc:src/verdict.ts:export async function judge}}
Measured honestly: no accuracy gain over the open model as decider, and in the matched ablation on /proof no attack was stopped by the guard alone. The guard also held 94 of 273 decision passes on clean Karak findings (obligations-v2), and each hold leaves a finding to your review.

Code owns the veto

What a model is never allowed to decide.

Every rule below is deterministic, tested, and runs after the model has spoken. The models propose; these decide what is allowed to stand.

citationsA link must resolve at its commit, sit in scope, and share an identifier with the finding's own text. Otherwise: citation broken, no model call. {{loc:src/citations.ts:export function markUnrelated}}
proof“Contains a test” (a test function with an assertion) and “concrete steps” are read from the finding by code; the model cannot claim more. Nothing in a finding is executed. {{loc:src/defenses.ts:export function proofInReport}}
scanText addressed to the pipeline (field names, dictated verdicts, fake judge comments, hidden text) removes READY and automatic routing. {{loc:src/defenses.ts:export function scanInstructions}}
capsREADY needs code support “yes”, a root cause that exists in the audited source, no blocking code, no known-issue match, no trusted-role precondition (code does not yet check the policy's exceptions for a trusted role, so such a finding is always left to your review), a test or concrete steps, every citation resolving, and no required item left in either the evidence or the decision. Each missing item names which of five acceptance obligations it affects; items that only strengthen a finding do not block it. Any miss: needs proof, with an item saying what would resolve it. {{loc:src/caps.ts:export function applyCaps}}
negativesA “no” is held to the same standard as a “yes”. “Blocked by code” must name blocking code that exists. “Known or out of scope” must quote a clause or bot finding that appears in the contest policy. Code can verify that the reference exists, not that it applies, so a model “no” is always shown with its grounds and left to your review. A broken code link is the one automatic result: it asks you to repair the link, not to drop the finding. {{loc:src/policy.ts:export function groundedClause}}
reconcileEach requirement the evidence step raises is numbered. The decision must carry it forward by number and obligation, and the evidence step's own wording is what you see; otherwise the gap is left to your review. The checklist you see is the one code enforced. {{loc:src/caps.ts:const uncarried}}
consensusThree passes. Unanimous, unflagged, not overruled and not a “no” is automatic advice; anything else needs your review. {{loc:src/precheck.ts:export function consensus}}
receiptEvery check returns an Assay Receipt with a SHA-256 checksum over finding digest, audited commit, votes, request ids and cost. It detects edits; it does not prove who issued it or that the verdict is right. {{loc:src/certificate.ts:export function issue}}
